# הוראות ההרצה השבועית

זה המפרט שהמשימה המתוזמנת מריצה כל יום ראשון בבוקר. הוא נכתב כדי שאפשר יהיה גם להריץ אותו ידנית: פשוט להעתיק אותו לצ'אט חדש בתיקיית הפרויקט.

---

## המשימה

הפק גיליון שבועי חדש של "רדאר AI" ופרסם אותו.

## שלב 1 — המקור הראשי: הניוזלטרים במייל

בתיבת ה-Gmail המחוברת, משוך את כל מה שהגיע בשבעת הימים האחרונים מהשולחים הבאים:

| ניוזלטר | שולח | תפקידו בגיליון |
|---|---|---|
| The Rundown AI | `news@daily.therundown.ai` | דופק יומי, מוצרים וכלים |
| TLDR AI | `dan@tldrnewsletter.com` | מחקר וכלים, זווית טכנית |
| The Batch | `the-batch@deeplearning.ai` | פרשנות מחקרית שבועית |
| Import AI | `importai@substack.com` | מדיניות, ביטחון, גיאופוליטיקה |
| Exponential View | `exponentialview@substack.com` | מאקרו — כלכלה, אנרגיה, חברה |
| Ben's Bites | `bensbites@substack.com` | גיוסים, עסקאות, סטארטאפים |
| Payload | `newsletter@payloadspace.com` | חלל מסחרי ומדיניות חלל |

שאילתת Gmail:

```
newer_than:8d from:(daily.therundown.ai OR tldrnewsletter.com OR deeplearning.ai OR importai@substack.com OR exponentialview@substack.com OR bensbites@substack.com OR payloadspace.com)
```

קרא כל הודעה ב-`PLAIN_TEXT`. **התעלם מפרסומות** — כל בלוק שמסומן `TOGETHER WITH`, `PRESENTED BY`, `SPONSORED` או `*Sponsored Listing` הוא תוכן ממומן ולא נכנס לגיליון.

**זה המקור הראשי של הגיליון.** לפחות שני שלישים מהאייטמים חייבים להתחיל כאן — סיפור שאחד הניוזלטרים כיסה. סיפור שמופיע בכמה ניוזלטרים במקביל הוא אות שהוא חשוב; סיפור שאף ניוזלטר לא נגע בו צריך סיבה טובה להיכנס.

## שלב 2 — השלמה מהרשת (משני)

הרשת משלימה, לא מחליפה. שלושה שימושים לגיטימיים: (1) אימות והרחבה של סיפורים מהניוזלטרים — המקור המקורי, המספרים המדויקים, ההודעה הרשמית; (2) זוויות שהניוזלטרים מפספסים, בעיקר חלל ו-AI וישראל; (3) מה שקרה אחרי שהניוזלטרים נשלחו. עד שליש מהאייטמים יכולים להגיע מהרשת בלבד, ורק אם הם ברף של ספוטלייט. הרץ חיפושים על:

- שחרורי מודלים והשקות מרכזיות של השבוע
- מדיניות ורגולציה — ארה"ב, האיחוד האירופי, ישראל
- גיוסים, רכישות ומהלכי שוק משמעותיים
- **AI וחלל** — הזווית של מנהלת החלל: מחשוב מסלולי, ניתוח תמונות לוויין, אוטונומיה של חלליות, AI בתעשיית החלל הישראלית

## שלב 3 — כתוב את הגיליון

```bash
node scripts/new-digest.mjs
```

זה יוצר `content/digests/<תאריך>.json` עם מספר גיליון רץ. מלא אותו:

- **`title`** — כותרת שמזהה את הנושא של השבוע, לא "סיכום שבועי". תיאורית, לא מתחכמת.
- **`intro`** — 2–3 משפטים. מה החוט שמחבר את השבוע.
- **`spotlight`** — בדיוק שלושה סיפורים, הגדולים ביותר. לכל אחד `summary` ו-`whyItMatters` שאומר משהו לא טריוויאלי.
- **`sections`** — קבץ את השאר. כותרות מקובלות: מודלים ותשתית · מחקר וכיוונים חדשים · מדיניות ורגולציה · כלכלה ושוק · חלל ו-AI. השמט מדור ריק במקום להמציא לו תוכן.
- **`quickHits`** — 4–6 שורות בודדות, משפט כל אחת.
- **`sources`** — רק הניוזלטרים שבאמת תרמו לגיליון הזה.
- **`origin`** (חובה, לכל אייטם) — מאיפה הסיפור *התגלה*: `"newsletter:TLDR AI"` (השם בדיוק כמו בטבלה של שלב 1) או `"web"`. `url` עדיין מוביל למקור המקורי; `origin` מתעד את הגילוי, והאתר מציג "דרך TLDR AI" ליד המקור. זה מה שמאפשר לבדוק שהניוזלטרים באמת המקור הראשי.
- **`note`** — רק אם יש משהו חריג להסביר. אחרת מחק את השדה.
- **`links`** (אופציונלי, לכל אייטם) — עד 2 קישורי העשרה מעבר ל-`url`: סרטון הסבר טוב, ניתוח עומק, או כתבת רקע. רק אם באמת מצאת משהו ששווה את הקליק — `label` קצר ומתאר ("סרטון: איך זה עובד", "הסבר: מה זה X"). אל תמציא קישורים.
- **`podcast`** (אופציונלי, לגיליון) — נתיב לקובץ אודיו. מתמלא על ידי `node scripts/notebook.mjs audio` כשמאיה מורידה Audio Overview מ-NotebookLM (ראה `docs/NOTEBOOKLM.md`); אל תמלא ידנית.
- **`notebook`** (אופציונלי, לאייטם או לגיליון כולו) — קישור למחברת NotebookLM משותפת לשאלות על החומר. מתמלא כשמוגדר; אל תמלא ידנית.

### שלב 3.5 — תמונות רקע

אחרי שה-JSON מלא, הרץ:

```bash
node scripts/fetch-images.mjs content/digests/<תאריך>.json
node scripts/compress-images.mjs
```

הראשון מושך תמונת שער מכל כתבה ושומר ל-`public/img/<slug>/`; השני מקטין ל-1080px ודוחס.

**המטרה: לכל אייטם תמונה.** הסקריפט מנסה כמה סוכני דפדפן, og:image, twitter:image, JSON-LD וגרסת AMP. אם אייטם עדיין נכשל (חומת תשלום — WSJ, The Information, Bloomberg), חפש ברשת כתבה נגישה על **אותו סיפור** והוסף לאייטם:

```json
"imageFrom": "https://techcrunch.com/כתובת-הכתבה-החלופית"
```

ואז הרץ שוב את `fetch-images.mjs`. אפשר גם `"imageUrl"` עם כתובת ישירה לתמונה. אל תשתמש בתמונה שאינה קשורה לסיפור — אייטם בלי תמונה עדיף על תמונה מטעה, והעיצוב נופל בחן חזרה לגרדיאנט.

### כללי כתיבה

- **האתר הוא פיד אנכי בסגנון טיקטוק — כל אייטם הוא מסך מלא בנייד; לחיצה על הטקסט פותחת אותו לקריאה מלאה.**
  הכרטיס מציג את ~5 השורות הראשונות של `summary` ואת ~4 הראשונות של `whyItMatters`; הפתיחה מציגה הכל.
  לכן: `summary` 60–120 מילים, **המשפט החשוב ביותר ראשון** — מי שלא פותח חייב לצאת עם העיקר.
  `whyItMatters` 30–70 מילים באותו עיקרון.
- **עברית.** שמות מוצרים, חברות ומודלים נשארים באנגלית.
- **מספרים ספציפיים.** "פי 3.6 מהר יותר" ולא "משמעותית מהר יותר".
- **סימון מקור.** דיווח לא מאומת הוא "לפי דיווח". מדדים של חברה על עצמה הם "לפי המדדים שלה".
- **בלי הייפ.** בלי "מהפכני", "משנה משחק", "פורץ דרך".
- **`url` מוביל למקור המקורי** — לבלוג של החברה או לכתבה, לא לניוזלטר שציטט אותם.
- אם שבוע היה שקט, גיליון קצר עדיף על מילוי מלאכותי.

## שלב 4 — בדוק ופרסם

```bash
npm run build
```

הבנייה חייבת לעבור נקי. אחר כך:

```bash
git add -A
git commit -m "גיליון <מספר> — <תאריך>"
git push
```

ה-remote הוא `github.com/yaligolan27/Weekly-AI-Newsletter` (ציבורי, ענף `main`; הענף המקומי נקרא `clean-main` ונדחף עם `git push origin clean-main:main`), ו-Vercel בונה ומפרסם ממנו אוטומטית תוך כדקה.

## שלב 5 — דווח

שלח למאיה הודעה קצרה: מספר הגיליון, הכותרת, הלינק, ושורה על מה היה הסיפור הגדול. אם משהו נכשל — אמור מה נכשל ומה לא נכנס לגיליון.

צרף גם את הפלט של `node scripts/notebook.mjs sources <תאריך>` — רשימת הקישורים שמאיה מדביקה ב-NotebookLM (ראה `docs/NOTEBOOKLM.md`). ציין את החלוקה לפי `origin`: כמה אייטמים מהניוזלטרים (ואילו ניוזלטרים) וכמה מהרשת. אם פחות משני שלישים מהניוזלטרים — הסבר למה.
